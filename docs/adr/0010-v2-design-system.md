# Replace the paper design system with v2

The client's appearance follows `docs/DESIGN.md` v2, which replaces the first design system entirely rather than amending it. The first system drew everything as one text shape on warm paper: Literata only, whitespace as the only separator, no boxes, no controls that looked like controls — every action a grey word that turned ink. It read calmly in screenshots and poorly in use: nothing on a screen said what could be pressed, a destructive word sat beside a harmless one with only colour between them, and each new control had to invent another way of being a word. v2 keeps the calm and gives interaction one visible shape: every control is a hard-edged grey block of one height, one black block marks the single primary action on a screen, and a link is the only text that acts on its own. Type is split by job: Literata for what the User reads, Instrument Sans for what they operate. The interface itself is greyscale, and colour appears only in data — Cadence, saved state, search matches — blue in light mode and yellow in dark.

This supersedes the styling half of ADR 0008. That ADR's behavioral decisions stand unchanged: interactive behavior comes from Base UI, styling is the client's own semantic classes keyed on the library's `data-*` state, and an overlay is for a decision that must be resolved before continuing, never for information. What changes is how an overlay is drawn. ADR 0008 drew it as the same paper with no border and no shadow, separated only by the dimmed backdrop; v2 draws a white panel with a hairline ring and a soft shadow on desktop, and a hard-edged sheet rising from the bottom edge on a phone. Its motion rules carried over until the amendment below.

The words on screen stay the domain's. The v2 mockups say "Sources", "posts", "Full article" and "Activity"; `CONTEXT.md` names those as synonyms to avoid, and "Source" already means something else in **Reading Source**. The shipped copy says Feeds, items, Original webpage and Cadence, and `docs/DESIGN.md` lists every word it changed.

Two costs are accepted. The client ships a second typeface, which the first system forbade outright. And some of what the mockups draw needs data the API does not serve yet — Digest views by day and by source, a Show in digest setting, per-Feed statistics beyond Cadence. Until the server serves it, the client leaves it out; it never approximates it from a partial page, which is why a group's count appears only once the whole group has loaded.

**Amendment (motion).** The v2 motion faded each screen as a whole, so the chrome the User had just opened was what moved, while the items, which arrived a moment later, cut in; a fast answer flashed the waiting line for a frame; and the Original webpage replaced Feed Content with no transition. Motion now follows the rule the palette does — colour only in data, motion only in data: a screen's chrome is instant and only what the server sends fades in (`docs/DESIGN.md` §7). Two of ADR 0008's overlay rules change with it. On a phone the dialog is a sheet, and a sheet that fades in place contradicts the edge it is drawn against, so it rises from the bottom edge and sinks back while the scrim fades; the desktop panel stays opacity only. And under `prefers-reduced-motion` the overlay fades stay: reduced motion removes movement, not the fades that say something appeared, so the sheet fades in place instead of rising. Every other dismissal stays instant.
