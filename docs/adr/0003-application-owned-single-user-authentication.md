# Use application-owned single-user authentication

Simple RSS owns a password-based login rather than requiring Cloudflare Access or an external identity provider. A one-time setup secret establishes the User, passwords use Argon2id, opaque sessions live in SQLite, and login attempts are rate-limited; this adds a small security-sensitive module but keeps the Docker deployment portable and self-contained without introducing registration, recovery email, OAuth, roles, or multi-user accounts.

**Amended (Sessions under the verifier).** A Session exists only under the current password verifier. `CredentialStore.issueSession` reads the verifier inside the transaction that inserts the Session and issues nothing if the verifier the caller checked has since been replaced, and `changePassword` and `resetPassword` replace the verifier and delete every Session in one transaction. A sign-in racing a password change or a CLI reset therefore cannot leave a Session behind under the old password; the sign-in that loses the race is rejected. Changing the password signs out every device, the one that asked included: the route clears its cookie and the User signs in again with the new password. The rule has no exception, so every live Session was issued under the verifier now stored.

**Amended (Credential bounds and hashing cost).** Argon2id runs with 19 MiB of memory, two passes, and one lane (`auth/password.ts` `ARGON2ID_PARAMETERS`), the second of OWASP's recommended Argon2id configurations. A chosen password is at least 12 characters. Every password, chosen or presented, is at most 512 characters and 1024 UTF-8 bytes (`shared/api.ts` `fitsPasswordBytes`); the byte bound is the one that matters, because Argon2id hashes bytes and one character can take up to four. A password over it is refused before any hashing, so an oversized body costs the server nothing. A presented password, at sign-in or as the current password in a change, is held only to being non-empty within that ceiling, and the verifier decides; the minimum length applies only when a password is chosen. The Setup Secret must be at least 16 characters. A shorter one leaves setup unavailable with the reason `setup secret is too short`, because anyone who reaches an unclaimed installation can guess at it and a short secret protects nothing.

**Amended (Counting an attempt before checking it).** One limiter, `LoginRateLimiter`, guards every route that checks a secret, per client address and across the installation; its thresholds and delays are in `docs/ARCHITECTURE.md`. `begin` records the attempt as a failure, timed from its start, before the secret is checked. The attempt's first outcome settles that record: a failure keeps it, a success forgets every record for that client, and a cancel (an error, or a sign-in that lost the race above) removes only its own record. Counting at the start means parallel attempts are each counted before any of them is checked, so a burst of concurrent guesses cannot pass either limit. The installation-wide refusal at a hundred records in the window is checked before a record is added, so the list never holds more than a hundred: however many addresses a caller rotates through, the limiter's memory and the cost of each `begin` stay bounded.
