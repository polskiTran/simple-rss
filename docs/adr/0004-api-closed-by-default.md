# Close the API by default

Every route under `/api` requires the User's session except the exact paths `/api/auth/status`, `/api/auth/setup`, and `/api/auth/session`; `/health/*` stays open for platform probes. Mounting a route under `/api/auth` does not make it public: each exception must be added to the allowlist deliberately. New routes are therefore private unless explicitly exempted, rather than private only when someone remembers to guard them; `/api/meta` moved behind the session for the same reason, which costs an unauthenticated caller the version string and costs the smoke tests one claim. This is what makes "before setup, only setup and health are reachable" a property of the router instead of a rule each future ticket has to re-apply.

**Amended (Same-origin requests).** Ahead of the session guard, every `/api` request whose method is not `GET`, `HEAD`, or `OPTIONS` must carry an `Origin` whose host equals the request's `Host` and whose scheme is the one the browser used (`http/same-origin.ts` `sameOrigin`). It applies to the allowlisted auth paths too, so another site cannot sign a browser in or claim the installation from a form. A request without `Origin` is refused: the only client is the browser application, and browsers always send `Origin` on these methods, so the refusal costs it nothing and leaves no unchecked path for a state change. `Origin: null`, which a sandboxed frame sends, never matches, since it names no host. Behind the TLS-terminating proxy the scheme comes from `X-Forwarded-Proto` under the proxy trust decision in [ADR 0019](./0019-trust-the-nearest-proxy.md).

**Amended (Identifiers that name nothing).** A Feed or Feed Item identifier in a path that does not parse answers the same `404 not_found` as a well-formed one the installation does not hold (`http/requests.ts` `readId`), never a `400`. Neither names anything this installation holds, so they are one answer.
