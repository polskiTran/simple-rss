# Retrieve the outside world through one hardened boundary

Feed polling, Reader extraction, and the image proxy all retrieve through one deep module in `src/server/upstream` rather than calling `fetch` or a raw HTTP adapter. Callers state the operation — `feed`, `reader`, or `image` — and the module owns that operation's content types, decoded-byte ceiling, deadline, redirect policy, and concurrency budget. Callers may supply the validators for a conditional request, a trace id, or cancellation, but cannot broaden a profile or skip a safety check. Every profile permits HTTP and HTTPS only, rejects URL credentials, localhost, non-global addresses, and the installation's required canonical `PUBLIC_ORIGIN`, independently revalidates every redirect within five hops, applies one deadline from queueing through the final response headers and a second to the last decoded byte, and returns a fixed set of safe failure categories. One development exception exists. `ALLOW_RESERVED_FETCH_DESTINATIONS=true` outside production allows the IPv4 benchmarking range 198.18.0.0/15, because some sandboxes answer every lookup with 198.18.0.1. `NODE_ENV=production` ignores the variable and the process warns once at startup. No other non-global range is exempt. The module exposes no arbitrary-URL HTTP route.

The raw network adapter is an internal seam of the retrieval module, not a dependency available to Feed, Reader, image, or HTTP modules. Each hop's name is resolved once, by the destination check; the adapter's socket is pinned to the addresses that check approved and never resolves again, so there is no DNS-rebinding window, while TLS still names and verifies the URL's host. It never follows redirects, fully decodes every declared supported content encoding, rejects unknown or malformed encoding chains, and closes the underlying connection when work is cancelled or exceeds its limit. Tests of callers inject `Retrieval`, while tests inside `src/server/upstream` may replace the adapter and resolver to model slow, moving, oversized, lying, redirecting, and compressed publishers.

Resource limits apply to the process as a whole, not merely to one publisher: DNS work, queued and active retrievals, decoded bytes, and open or idle sockets are bounded globally, with smaller operation budgets preventing one kind of work from starving another. `private` and `reserved` mean every address that is not globally reachable under the IANA IPv4 and IPv6 special-purpose registries, including embedded IPv4 forms. The cost is maintaining a small Node `http`/`https` adapter and the registry classification. The rejected alternative — per-caller `fetch` plus shared helpers — makes every safety rule optional, while a generic caller-configured retrieval interface would move policy knowledge back into each future feature.

**Amended (Two deadlines).** Each profile carries two deadlines, not one. `timeoutMs` starts before the retrieval queues for capacity and covers queueing, resolution, connection, and every redirect hop up to the final response's headers; `bodyTimeoutMs` starts at those headers and covers the body to its last decoded byte (`upstream/retrieval.ts` `RETRIEVAL_PROFILES`: ten seconds to answer for every operation, then sixty for a Feed or discovery body and thirty for a Reader page or an image). One timer for both made a Feed that was slow to send a large body report itself as a Feed that never answered. They fail as `timeout` and `body_timeout`, which the User is told apart and which Feed Availability stores as one `timeout` category. The body deadline is armed on the body stream itself, so it fires whether or not anyone is reading: a caller that never reads or cancels a body cannot hold its capacity slot past the deadline. A deadline that passes mid-body errors the stream rather than closing it, so a truncated body never passes for a whole one.

**Amended (The body contract).** `retrieve` returns the body as a stream and holds the operation's capacity slot until that stream ends; the caller must read it to the end or cancel it, and the slot is released only then. `retrieveBytes` reads it for the caller and returns bytes that own their whole `ArrayBuffer`, allocated fresh at offset zero with nothing else in it, so a caller may transfer `bytes.buffer` to a worker. A failure's `reason` names the rule that refused, never URL credentials or a query string, so it is safe to log; it is never shown to the User, whose text comes from the failure code (`http/retrieval-answers.ts`). Since ADR 0012 there are four operations: `discovery` accepts web pages as well as Feeds, for the Add feed preview.

**Amended (What the destination check refuses).** The check resolves every address a name answers with, and one address that is not globally reachable refuses the whole name, since a mixed answer is how a rebinding attempt looks. Names that are, or end in, `localhost`, `local`, `internal`, or `arpa` are refused by name before any resolution, because inside a deployment such names can resolve differently than on the host and an address check could pass them. Hostnames are compared without a trailing dot, which `URL` keeps, so `example.com.` cannot slip past a rule for `example.com`. The installation's own `PUBLIC_ORIGIN` is matched by host and effective port, not scheme, because the platform proxy may answer HTTPS outside while the service answers HTTP inside; a Feed or Feed Item link can therefore never steer a retrieval into the installation's own API, which is why `PUBLIC_ORIGIN` is required.

**Amended (Holding the pin in the adapter).** Node does not call `lookup` for a host that is an address literal, so the adapter checks a literal against the approved addresses itself (`upstream/network-client.ts`). The pinned lookup honours the `family` and `all` options Node passes, so a dual-stack connection attempt chooses only among the approved addresses. The keep-alive agents set no `maxSockets`: a Node agent queues requests over its cap, a queued request cannot be destroyed until a socket frees, and a cancelled retrieval would then wait on some unrelated retrieval letting go of its socket. The Retrieval gates bound concurrency instead, and the agents only pool idle sockets, each still connected to an address an earlier check of the same host approved. A cancelled request rejects at once, whatever state it is in, rather than waiting for the destroyed request to report an error.

**Amended (The registry as a table).** `upstream/addresses.ts` classifies an address from one table per family, each row a CIDR prefix with its registry name and either the class it gives or, for the IPv4-mapped, NAT64 and 6to4 prefixes, the byte offset of the IPv4 address it carries, which the IPv4 table then judges. The narrowest prefix that contains the address decides, as in a routing table, so a globally reachable exception such as 192.0.0.9/32 sits beside its /24 and row order means nothing. An address no row contains is `public` in IPv4 and `reserved` in IPv6, where only 2000::/3 is listed as global unicast; IPv6 therefore fails closed, and the rows for ::/96, 64:ff9b:1::/48 and 100::/64 restate that default so the table still reads against the registry. The documentation block 3fff::/20 is held as the whole unassigned 3ff0::/12 that contains it. A row whose address sets bits past its prefix length fails at startup rather than matching a range nobody wrote. `tests/server/upstream/addresses.test.ts` pins the first and last address of every row and one address beside it.
