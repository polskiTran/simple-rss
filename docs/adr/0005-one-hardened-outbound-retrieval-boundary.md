# Retrieve the outside world through one hardened boundary

Feed polling, Reader extraction, the image proxy, and the subscribe flow's proving of a pasted address all retrieve through one deep module in `src/server/upstream` rather than calling `fetch` or a raw HTTP adapter. Callers state the operation — `feed`, `reader`, `image`, `preview` for a Feed a User is waiting on, `discovery` for a page read for its Declared Feeds — and the module owns that operation's content types, decoded-byte ceiling, deadline, redirect policy, and concurrency budget. Callers may supply conditional headers or cancellation, but cannot broaden a profile or skip a safety check. Every profile permits HTTP and HTTPS only, rejects URL credentials, localhost, non-global addresses, and the installation's required canonical `PUBLIC_ORIGIN`, independently revalidates every redirect within five hops, bounds the whole retrieval from queueing and DNS through the last decoded byte, and returns a fixed set of safe failure categories. How a profile keeps that bound is its own: the scheduled operations give the answer and its body separate clocks, so a slow large body is not an unreachable host, while the operations a User waits on run one clock over both; and the `discovery` ceiling truncates rather than refuses, since Declared Feeds sit in a page's head and the rest of the page is not worth a refusal. The module exposes no arbitrary-URL HTTP route.

The raw network adapter is an internal seam of the retrieval module, not a dependency available to Feed, Reader, image, or HTTP modules. Its socket lookup validates every resolved address immediately before connection, closing the DNS-rebinding window; it never follows redirects, fully decodes every declared supported content encoding, rejects unknown or malformed encoding chains, and closes the underlying connection when work is cancelled or exceeds its limit. Tests of callers inject `Retrieval`, while tests inside `src/server/upstream` may replace the adapter and resolver to model slow, moving, oversized, lying, redirecting, and compressed publishers.

Resource limits apply to the process as a whole, not merely to one publisher: DNS work, queued and active retrievals, and decoded bytes are bounded globally, with smaller operation budgets preventing one kind of work from starving another — the shared concurrency is the sum of those budgets, so scheduled polling at full tilt never queues the operations a User is waiting on. Sockets are bounded by those same gates: a connection exists only while an admitted retrieval uses it and none is kept idle, so the adapter carries no socket cap of its own. `private` and `reserved` mean every address that is not globally reachable under the IANA IPv4 and IPv6 special-purpose registries, including embedded IPv4 forms. The cost is maintaining a small Node `http`/`https` adapter and the registry classification, plus a connection handshake per retrieval. The rejected alternative — per-caller `fetch` plus shared helpers — makes every safety rule optional, while a generic caller-configured retrieval interface would move policy knowledge back into each future feature. Keep-alive connections behind a socket cap were tried and removed: idle connections counted against the cap and could hold an admitted retrieval behind publishers that had already answered, and the reuse bought little when a Feed host is polled minutes apart and the browser caches images.
