# Check a Subscription before recording it; OPML Import still records first

Adding a Feed from the Add feed dialog is two requests: a preview, then Subscribe. The preview retrieves the entered address through `Retrieval` (ADR 0005) and records nothing. An address that answers with RSS or Atom comes back as that Feed, summarised: its reported title, its Cadence over the last 30 days, when its newest Feed Item was published, its five newest Feed Items, and whether it is already subscribed. An address that answers with a web page is read for its Declared Feeds, in page order; the first five are each retrieved once and summarised the same way, and a declared address that answers with another page is not followed further. A page that declares no Feed, or an address that does not answer, comes back as the reason. Subscribe then sends the chosen Feed's URL, and the server retrieves it again within the request: only if it answers with RSS or Atom are the Feed and Subscription recorded and the Feed Window ingested. Otherwise the request is refused with the reason and nothing is recorded. A Subscription added by hand has therefore been reached at least once, and never starts unchecked.

ADR 0007's two reasons for recording first both came from bulk import: a 136-feed import held one request open for minutes, and a Feed that failed its single check left no row for anything to retry. Neither holds for one Feed added by hand. Its check is a single retrieval bounded by `Retrieval`'s timeouts, and the User is watching the dialog, so a failure is theirs to act on — Retry, or another address — rather than the scheduler's to retry forever. Checking before recording also catches what recording first never could: a Feed that answers but has published nothing in years, which the User sees in the preview and cancels, instead of finding it again later to unsubscribe. Two alternatives were rejected. "Subscribe anyway" for an address that does not answer would bring never-reached Subscriptions back to the one path that can avoid them: a Feed the server cannot reach now — a site that is gone, or one that refuses the server's address — rarely starts answering, and Retry covers a passing outage. Letting Subscribe trust the preview's retrieval, to save the second one, would need either a server-side cache of previews or Feed Items sent back by the client; one more retrieval is cheaper than either.

OPML Import keeps ADR 0007 unchanged: it records every listed Feed without contacting any, unchecked and immediately due, and a first retrieval that reveals an already-subscribed Feed merges into it. Someone importing a hundred Feeds expects all of them listed, and Feed Availability is how the ones that never answer are shown. Declared Feeds are found only by the preview: neither import nor polling reads pages, so a page URL that reaches the scheduler fails as unsupported content, as it does today. What this accepts: previewing a page spends up to six retrievals — the page and five Feeds — against `Retrieval`'s budgets, and a Feed added by hand is retrieved twice, once to preview and once to subscribe.

This narrows ADR 0007 to OPML Import.
