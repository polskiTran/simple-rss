# Take the client's interactive behavior from Base UI

The client takes its interactive behavior from Base UI — `Button`, `Field`, `Toggle`, `Toggle Group`, and `Dialog` — and supplies every pixel of the styling itself, as semantic classes in `@layer components` keyed on the library's `data-*` state attributes. The library ships no CSS, so what changes is where behavior comes from, not what a screen looks like. Elements the platform already does well stay native and are not candidates for migration: the tab bar is `<a href>` links whose URLs are the routing state, the timezone control is a native `<select>` whose mobile picker beats any listbox over four hundred zones, the OPML Import control is a native file input, the Feeds add field is a plain URL input rather than a combobox, and Cadence grid cells stay plain buttons because wrapping a hundred and eighty-two of them buys nothing. The immediate return is `focusableWhenDisabled`: ten controls disable themselves while their request is in flight, and every one of them used to drop keyboard focus to the document body at the moment the User pressed it. Eight hold it now — the last of them, the overlay's dismissing word, only through composition: `Dialog.Close` accepts native button props alone, so it takes the behavior from `Button` through the `render` prop rather than going without. The timezone `<select>` and the OPML Import file input are the two that stay native, and they go on disabling and dropping focus exactly as they always have.

The global search line uses Base UI `Field` for its control behavior. Its `/`
shortcut remains application-owned because it coordinates focus from outside the
control rather than changing behavior inside it. The document listener yields
to inputs, textareas, selects, and editable content before moving focus.

An overlay is for a decision that must be resolved before continuing, never for information. `Dialog` and `Alert Dialog` qualify; `Toast`, `Tooltip`, and `Preview Card` do not, which is what keeps a deferred notice — an OPML Import's outcome, or the first check a new Subscription is still waiting on — in the `aria-live` line it already occupies. This replaces the design system's older rule that nothing floats over the paper, which unsubscribing broke: a confirmation that unfolds in place is hard to hold together on a phone. An overlay is drawn as the same paper with no border, no radius, and no shadow, its edge made only by the dimmed backdrop, so separation-by-whitespace becomes separation-by-dim rather than an exception to it. It is one component at every width — anchored to the bottom edge at 1024px and below rather than swapped for a drawer — because two interaction models for one confirmation is where a single design becomes two. Overlays are also the one place motion may run on exit: in at 150ms, out at 120ms, opacity only, both zero under `prefers-reduced-motion`, while every other dismissal stays instant.

Two costs are accepted. `Toggle Group` navigates with arrow keys under a roving tabindex, so the six Polling Interval words and the three appearance words each become one tab stop where they were six and three — the correct pattern, and still a change the User can feel. And the client gains a runtime dependency in a project that advertises one package and one image, though the components used pull in no positioning machinery and the design system absorbs no styling from it. `Form` was considered and left out, and should stay out: its two offers are a per-field `validate` callback and an `errors` map keyed by field name, and the password change holds neither shape. `reasonToHold` is one rule spanning both fields, shared verbatim with the setup screen, so a per-field callback would fix one caller and leave the other; and `describeFailure` returns whole-form sentences — "too many attempts — try again in 10 minutes", "the reader is unavailable" — that have no honest key in that map. Adopting it would split one rule in one of its two callers and move the notice out of the status line it belongs to. The rejected alternative for the rest is what the client has been running: hand-written elements carrying hand-written ARIA. That costs nothing until a surface needs a focus trap, a scroll lock, an escape key, and focus returned to its trigger — at which point it costs a week and is still wrong in the ways only a screen reader finds.

How an overlay is drawn is superseded by ADR 0010; the behavior above stands.

**Amended (native controls keep focus).** The two native exceptions above no longer drop focus. `components/native-select.tsx` `NativeSelect` stays a native `<select>`, but while its caller saves it takes `aria-disabled` and `aria-busy` instead of `disabled`, and its change handler ignores a choice; the select is controlled, so it goes on showing the held value. That matches what `focusableWhenDisabled` does for a Base UI `Button`, and the select keeps keyboard focus while busy. It serves the installation timezone and a Feed's Check every, which replaced the six Polling Interval words with a native select, so the Polling Interval is no longer a `Toggle Group` and the tab-stop cost above applies to the appearance words and the other switches only. The OPML Import file input is not disabled while an import runs: the Import button, a Base UI `Button` with `focusableWhenDisabled`, holds focus, and the dialog refuses to close until the import answers. What this accepts: a busy select still opens the platform's picker, and a value chosen there is dropped rather than refused visibly. One more composition rule joins `Toggle Group`: Base UI lets a press on the pressed segment empty the group, and a switch always holds one value, so `components/choice.tsx` `Choice` ignores a change that would leave nothing chosen.
