# Render articles with Streamdown, trimmed and styled by the client

The Reader View renders Feed Content and the Original webpage as Markdown with Streamdown (`components/article-markdown.tsx` `ArticleMarkdown`), imported lazily by `views/reader-view.tsx` so the rest of the client never loads it. Streamdown parses; the client draws. Prose blocks (headings, lists, quotes, rules, tables, links, images) are overridden with plain elements and styled by the stylesheet's `.article-body` rules (`docs/DESIGN.md` §5 Reader), not by Streamdown's utility classes. Code blocks stay Streamdown's, for their highlighting, with its controls turned off. Highlighting is Shiki through `components/article-code.ts` `articleCode`, which tokenizes with the light and the dark theme in one pass: each token carries its light colour and a `--shiki-dark` variable, the shape Streamdown's `dark:` classes read, so a change of Appearance needs no second highlight.

What remains of Streamdown's styling is bound to the design system in `styles.css`. `@source` points Tailwind at Streamdown's built files so the classes they name are generated. Tailwind's `dark` variant is redefined with `@custom-variant dark` to follow `data-appearance` first and the system setting second, as the tokens do, so Streamdown's `dark:` classes follow the User's Appearance rather than the system alone. `--color-background`, `--color-foreground`, `--color-border`, `--color-primary`, `--color-muted`, `--color-muted-foreground` and `--color-sidebar` exist only because Streamdown's classes name them; they alias design tokens, and the client's own rules use the design tokens. The code-block rules (`[data-streamdown='code-block']` and its parts) sit outside every `@layer`, because an unlayered rule outranks the layered utility classes Streamdown puts on the same elements; they square the block to the system and hide the language header, since a reader has nothing to operate there. KaTeX's math is set at 1.05em instead of its own 1.21em, so an equation reads at the size of the prose around it. Display math gets 2px of block padding, because KaTeX hangs glyphs outside its own box and the horizontal scroller would clip them. A numbered equation is widened to its content with 3.5em of padding on both sides, because KaTeX hangs the number at the box's right edge, on top of any formula wider than the column; the padding moves the number clear and keeps the formula centred.

The build keeps out what Streamdown would bring and the client never runs. Streamdown imports `rehype-raw`, and parse5 with it (about 170 kB), whether or not raw HTML is rendered. The client renders no raw HTML (`article-markdown.tsx` drops `raw` from Streamdown's default rehype plugins), so `vite.config.ts` aliases `rehype-raw` to `src/client/no-raw-html.ts`, a plugin that does nothing. Raw nodes stay unrendered either way; only the bundle changes. The lazy renderer's chunk is renamed `article-renderer` in `chunkFileNames` and `assetFileNames` rather than grouped with `manualChunks`, because the entry preloads a manual chunk group, which would defeat the lazy import; its default name, `mermaid-*`, comes from Streamdown's Mermaid stub, which this build does not ship. Fonts are never inlined as `data:` URLs (`assetsInlineLimit`): the server's content security policy loads fonts from `'self'` only (`http/security-headers.ts`), and the smallest subsets of the variable faces fall under Vite's 4 KB inline limit. The cost is a dependence on Streamdown's internals: the alias, the chunk name and the variable names have to be checked against each Streamdown upgrade, by building and reading the chunk names and the Reader View's code blocks.
