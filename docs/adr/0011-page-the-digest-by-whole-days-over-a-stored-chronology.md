# Page the Digest by whole days over a stored chronology

The chronology is a stored column. `feed_items.chronology_at` is generated from the item's own facts — its publication time, unless missing or more than a day past its first sighting, then first-seen — and indexed in the order pages walk it, across the Digest and within each Feed. Nothing in the rule reads the clock, so an item's place is fixed when it arrives and never moves. The Digest, the Reader's next in the Digest (`DigestService.after()`), an opened Feed's items, and Search's Newest order all sort by it directly. What this accepts: a post published ahead of its date — a scheduled announcement, an event — sits at its first sighting and does not resurface when the date comes.

`GET /api/digest` answers whole installation-timezone days, newest first. The Digest is read a day at a time — each Feed's items that day in one box, with the day's Feeds counted above — and a page cut mid-day would split a box and miscount the day. So a page takes the first fifty items along the chronology, then completes the day the fiftieth falls on; `nextFrom` names the next older day with items, and it is the same `?from=` a day picked on the calendar sends, so paging and picking a day are one request. An offset was rejected because polling inserts at the top and every offset drifts between requests; a day key is unmoved by arrivals above it, and with a stored chronology no item can cross it either. What this accepts: a busy day comes whole however long it runs. Fifty is a server constant, not a parameter. The Digest takes no filters — folding and the day's Feed counts answer the busy Feed that narrowing by Rhythm or by Feed was for.

The other lists page by what they are for. The Library pages by when each item was saved — newest or oldest save first (`?order=oldest`) — with an opaque keyset cursor (an instant and a tie-breaking id, strictly beyond the last item shown) over `library_items.saved_at`; its internals never enter the API contract. Search is bounded at fifty with no cursor (ADR 0009). The Feeds list and an opened Feed's items come whole: the first is bounded by curation, the second by Retention.

This supersedes ADR 0006, whose keyset over a computed chronology this replaced in two steps — day pages for the Digest, then the stored column.
