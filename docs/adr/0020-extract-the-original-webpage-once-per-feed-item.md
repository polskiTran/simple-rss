# Extract an Original webpage once per Feed Item, inside a deadline, with a cooldown for pages that keep failing

Reader View's Original webpage is retrieved and extracted on demand and never stored (ADR 0009 keeps it out of Search for that reason). `reader/reader-service.ts` `ReaderService` runs at most one retrieval and extraction per Feed Item at a time, and every reader that asks while it runs waits on the same work. Each reader is answered within `READER_BUDGET_MS`, 4.5 seconds: a five-second limit on the User's wait, less half a second for the response and the render. Past it, the reader gets `article_deadline_exceeded` naming the stage it was in. Work that every waiting reader abandons before the deadline is aborted. Work that is still running when the deadline answers keeps going, and an article it finishes is kept for one minute, so the reader's next request finds it instead of starting again.

A page that keeps failing cools down. Five failed attempts, each within thirty seconds of the one before, answer `rate-limited` until thirty seconds after the last attempt, after which the count starts again. Only failures that say something about the publisher or the page count toward it: an unreadable page, and every retrieval failure except `cancelled` (the reader left, or the work was abandoned) and `busy` (this installation's retrieval gates were full and the request was never sent). Feed Availability draws the line elsewhere, for polls: it sets aside only `busy`, and a `cancelled` poll counts as `unreachable`. That difference is what the code does today; this ADR records it and does not decide whether it is intended.

Extraction runs in a worker thread (`reader/reader-extractor.ts`), and the page's bytes are transferred to it rather than copied, so the caller's `ArrayBuffer` is detached after the call and must not be read again. `reader/extract-article.ts` `extractArticle` builds the document with linkedom, not jsdom, because jsdom cannot parse the CSS in Defuddle's clutter selectors, and a selector error makes Defuddle keep the whole page. The document is built here and handed to Defuddle rather than left to Defuddle's own lazy linkedom loading, which does not survive every module loader. linkedom lacks `styleSheets` and `getComputedStyle`, which Defuddle calls, so `articleDocument` supplies both, and it sets `document.URL` to the post-redirect address so that relative links and Defuddle's site extractors resolve against where the page actually is.

Before Defuddle runs, scripts, styles, templates, and embeds are pruned, with three kinds of script kept: JSON-LD, which Defuddle reads for metadata; `math/*` scripts, which its standardization turns into math content; and MathJax or KaTeX loaders, because Defuddle treats raw `$…$` text as LaTeX only when it sees the page load a math renderer, and stripping them left client-rendered math to be escaped as prose. A synchronous Defuddle site extractor builds its own embed markup and can represent a page with no text as nothing but an embed. Such a result, with no words and an iframe, video, audio, object, or embed, is reported unreadable rather than rendered, so the Reader Markdown policy never turns it into an image.
