# Rank Search by match quality blended with recency

Every reading surface orders by the computed chronology, but Search leaves it: results order by BM25 match quality (FTS5's built-in, weighted Feed Item title > effective Feed title > summary) blended with a recency decay. Search exists for refinding, and refinding means a strong title match from three weeks ago must beat a weak summary match from this morning; pure chronology makes the search line a filter wearing a search field. Pure BM25 was rejected too: an RSS corpus repeats itself ("release notes" × twelve), and when text relevance ties, the recent item is almost always the sought one. Saved-state boosts were rejected as redundant — a result already shows its Library state.

Two boundaries this fixes on purpose. Relevance order is not keyset-able, so Search stays bounded at fifty results with no cursor, deliberately outside ADR 0006's page machinery: a refinding search line that misses in fifty is refined, not paged. And Search reads only what Feed Items carry — indexing Reader View text would mean persisting it, reversing the Reader View's deliberate ephemerality, so that is an explicit no rather than an omission.
