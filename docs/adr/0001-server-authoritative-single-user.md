# Use a server-authoritative, single-user model

Each self-hosted installation serves one User, and the server is authoritative for Subscriptions, Feed Items, Library membership, and preferences. Clients may cache views but will not replicate independent local databases; this keeps multi-device access predictable and avoids introducing conflict resolution into an intentionally simple reader.

**Amended (what makes the installation claimed).** The installation is claimed exactly when the one `user_auth` row exists; there is no separate flag. The row holds the User's Argon2id verifier, its table allows only `id = 1`, and claiming inserts it with `ON CONFLICT DO NOTHING`, so of two concurrent claims only the one whose insert lands gets a Session. Everything that asks whether the installation is claimed reads that row: setup, readiness, and the report of a restore, which therefore says a snapshot is claimed only if it carries a verifier. `reset-password` from the CLI writes the same row, so it also claims an unclaimed installation.

**Amended (Library membership).** Library membership is written only by the User: `LibraryService.save` and `unsave` are the only writers of `library_items`. Polling, ingestion, unsubscribing and Retention never add or remove a save; Retention reads it, to keep saved Feed Items. Saving is idempotent and a repeated save keeps the original saved time, so a second press or a retried request does not move the item in the Library, which pages by saved time (ADR 0011).

**Amended (HTTP caching).** No `/api` answer may sit in a shared or private HTTP cache, its 404s and 500s included: `createApp` sets `Cache-Control: no-store` on every `/api` response that has not set its own. A cached answer would show the User a Library state, a Digest or a sign-in state the server no longer holds. A route whose answer may be cached says so with its own `Cache-Control`, which the default leaves alone; Original webpage extraction and proxied images do.
