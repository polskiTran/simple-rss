# Run an experimental interface alongside v2

The client carries a second interface, chosen per device in Settings under Interface (`views/settings/interface-choice.tsx`). v2 is the default and stays complete; the experimental interface replaces it only where it has been designed — the Digest, a Feed and the Reader View — and hands every other screen back to the v2 view. The choice is a client-side `localStorage` key (`interface.ts` `INTERFACE`, read through `stored-choice.ts` `useStoredChoice`), like Appearance: it never reaches the server, removing the key returns to v2, and nothing about the installation, its API or its data differs between the two. The point is to try a different reading model on real Feeds without forking the client or putting v2 at risk; if the experiment earns its place, a later decision replaces v2 with it, and if it does not, deleting `src/client/experimental/` and the choice removes it.

`app.tsx` `App` picks the shell. With the access gate open and the experimental interface chosen, it renders `experimental/shell.tsx` `ExperimentalShell` with the v2 shell as its fallback; login and setup are always v2. The experimental shell reads the same address and history state as v2 (ADR 0028), so a link, a reload or Back lands on the same screen in either interface, and switching interfaces mid-session keeps the current address. Its designed screens use the same API calls as their v2 counterparts and add none. Feeds, Library, Settings, Search results and Add feed render the v2 view inside the experimental shell, reachable from the bloom's Go arm, and keep their v2 chrome.

This amends ADR 0010 for the experimental shell only. Its design system is its own, described in `docs/design/experimental/README.md` and drawn in `docs/design/experimental/index.html`: one 13px Geist size except the Reader View's body, twelve flush columns, no hairlines or borders, OKLCH, colour only in data, and Feed names coloured by their Rhythm. Its styles live in `experimental/experimental.css` under the `x-` prefix and apply only inside `.x`, or to the root while an `.x-page` is on screen, so v2 never sees them. Rhythm gains a Firehose tier for this interface's folding — 90 or more Feed Items in the last 30 days, checked before Daily (`shared/rhythm.ts`) — and because Rhythm is one domain term, v2's Feeds list groups by it too.

The bloom, the experimental shell's one menu, is the single exception to "motion only in data" (ADR 0010, motion amendment). Its shapes grow from the corner into four arms and fold back, and its arms fade in; that motion is chrome, and it is kept because the bloom's shape is how the User finds the four arms. Under `prefers-reduced-motion` every bloom and page-dim transition is removed, so it opens and closes at once. The screens themselves follow the motion rule unchanged.

ADR 0008 allows an overlay only for a decision that must be resolved before continuing. The bloom is allowed under it because leaving it is without consequence: it holds navigation, search and view choices, every choice in it applies at once, and dismissing it with Escape, a press outside or its core loses nothing and decides nothing. It takes its behaviour from Base UI `Dialog`, modal: focus moves into it (to its core, or to the search field when opened with `/`), stays trapped while it is open, and returns when it closes; the page beneath stops scrolling and becomes inert; Escape and a press on the backdrop dismiss it; `Dialog.Portal` keeps it mounted so its arms can be measured before it opens, and its enter and exit run on Base UI's `data-starting-style` and `data-ending-style`. The `.` and `/` shortcuts are application-owned, as the v2 search line's `/` is, and yield to editable targets; on screens that fall back to v2, `/` stays the v2 search line's. Its choices are Base UI `Toggle Group` and `Button` with `focusableWhenDisabled`.

ADR 0018 holds. Geist and Geist Mono ship in the bundle from `@fontsource-variable`, under the same no-inlining rule as the v2 faces, and the experimental screens show no publisher image except inside an article, which is the v2 `ArticleMarkdown` with its signed proxy paths. The prototype at `docs/design/experimental/index.html` loads Google Fonts and reads `.data/prototype-data.js`; it is a design reference opened from disk, never served by the installation, and outside the build.

What this accepts: two interfaces to keep working while the experiment runs, and a test suite that covers the experimental one only where it differs — its Digest grouping (`tests/client/firehose.test.ts`), the choice (`tests/client/settings.test.tsx`) and one user path (`tests/browser/experimental.spec.ts`).
