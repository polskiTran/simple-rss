# Run an experimental interface alongside v2

The client carries a second interface, chosen per device in Settings under Interface (`views/settings/interface-choice.tsx`). v2 is the default and stays complete; the experimental interface draws every screen behind the access gate — the Digest, the Feeds screen, a Feed, the Library, the Reader View, Search results and Settings. The choice is a client-side `localStorage` key (`interface.ts` `INTERFACE`, read through `stored-choice.ts` `useStoredChoice`), like Appearance: it never reaches the server, removing the key returns to v2, and nothing about the installation, its API or its data differs between the two. The point is to try a different reading model on real Feeds without forking the client or putting v2 at risk; if the experiment earns its place, a later decision replaces v2 with it, and if it does not, deleting `src/client/experimental/` and the choice removes it.

`app.tsx` `App` picks the shell. With the access gate open and the experimental interface chosen, it renders `experimental/shell.tsx` `ExperimentalShell` in place of the v2 shell; login and setup are always v2. The experimental shell reads the same address and history state as v2 (ADR 0028), so a link, a reload or Back lands on the same screen in either interface, and switching interfaces mid-session keeps the current address. Its designed screens use the same API calls as their v2 counterparts and add none; the Feed lookup behind Add a Feed is one hook, `views/feed-lookup.ts`, shared with the v2 Add feed dialog. A top bar on every screen links the Digest, the Library, the Feeds screen and Settings, and holds the search line, which submits to the experimental Search results.

This amends ADR 0010 for the experimental shell only. Its design system is its own, described in `docs/design/experimental/README.md` and drawn in `docs/design/experimental/index.html`: one 13px Geist size except the Reader View's body, twelve flush columns, no hairlines or borders, OKLCH, colour only in data, and Feed names coloured by their Rhythm. Its styles live in `experimental/experimental.css` under the `x-` prefix and apply only inside `.x`, or to the root while an `.x-page` is on screen, so v2 never sees them. Rhythm gains a Firehose tier for this interface's folding — 90 or more Feed Items in the last 30 days, checked before Daily (`shared/rhythm.ts`) — and because Rhythm is one domain term, v2's Feeds list groups by it too.

The experimental screens follow ADR 0010's motion rule unchanged, and add no overlay: every choice and action sits on the page, in the ledger rows of the screen it belongs to. The `/` shortcut is application-owned, as the v2 search line's is: it focuses the top bar's search line and yields to editable targets.

ADR 0018 holds. Geist and Geist Mono ship in the bundle from `@fontsource-variable`, under the same no-inlining rule as the v2 faces, and the experimental screens show a publisher image in two places only: a Feed Item's own image on the Digest's Columns and Wall layouts, through its same-origin path `/api/items/:feedItemId/image`, and an image inside an article, which is the v2 `ArticleMarkdown` with its signed proxy paths. An image the proxy refuses is dropped from its card, which then reads as text. The prototype at `docs/design/experimental/index.html` loads Google Fonts and reads `.data/prototype-data.js`; it is a design reference opened from disk, never served by the installation, and outside the build.

What this accepts: two interfaces to keep working while the experiment runs, and a test suite that covers the experimental one only where it differs — its Digest grouping (`tests/client/firehose.test.ts`), the choice (`tests/client/settings.test.tsx`) and its user paths (`tests/browser/experimental.spec.ts`): reaching a Feed and a Reader View from the top bar, searching and narrowing a search to one Feed, adding a Feed from the empty Digest, renaming and unsubscribing it, the Library, and switching back to v2 from Settings.
