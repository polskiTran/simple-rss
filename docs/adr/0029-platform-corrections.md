# Correct browser and font behaviour at the element it affects

Where a browser, a typeface or `Intl` does something the design system does not want, the client corrects it in the rule or component for the element concerned, not with a general layer of resets or wrappers. Each correction is small and reads as an arbitrary number or an odd property choice, so the reason for each is recorded here.

iOS Safari zooms the page into a focused control whose text is under 16px, so every field, the search input and every select is 16px on a phone. The phone Digest's day picker is a native `<input type="date">` laid invisibly over a calendar button (`views/digest-view.tsx`). A tap opens the platform's picker on a phone; its click handler calls `showPicker()` because a desktop browser in the narrow layout opens the picker only from the field's own icon. The button clips the input (`.day-picker`, `overflow: hidden`), because iOS Safari gives a date field a minimum width from its date text, and the invisible field would run past the screen edge and let the page drag sideways. An address field (`components/field.tsx` `Field` with `type="url"`) is a text input with `inputMode="url"`: a phone shows its URL keyboard, while the browser's URL validation, which refuses a bare host such as `lowtechmagazine.com`, stays out of the way, and the client adds `https://` itself (`views/feed-language.ts` `feedAddressOf`). A short month name is the long name cut to three letters (`day-names.ts` `shortMonth`), because `Intl` writes September's short form in `en-GB` as `Sept`.

A scroll container clips what its children draw outside its padding box, including outlines, so each one is given room. The phone's dialog sheet sits on the bottom edge by `margin-top: auto` rather than `justify-content: flex-end`: a flex-end item taller than its container overflows upward, where its top can never be scrolled to, while an auto margin overflows downward and keeps the title reachable. The row of a day's Feed chips bleeds out 4px with 4px of padding so a focus ring is drawn whole, and ends 32px past its last chip so that chip can scroll clear of the row's 32px trailing fade. The sticky column beside a list (the Digest's month, a Feed filter) bleeds out by a negative margin and the matching padding, so its own scrolling does not clip the rows' hover fill and focus ring. A Feed filter chip on a phone is `position: relative`, so the visually hidden checkbox it holds, which is absolutely positioned, stays inside the scrolling row instead of widening the page.

Some sizes are set by what a hand or an eye needs rather than by the drawn shape. The Feed name in an item box sits over the box's link to the Reader View; its hit area reaches 8px above and below its line, by padding with a matching negative margin, so a near miss opens the Feed rather than the article. Show all in a Feed's day box reaches past its text with a pseudo-element, 12px on each side on a phone, which brings it to about a control's height without reaching the first title below. The 48px page title is set 2px left (`.page-title`) so the side bearing of its large glyphs lines up with the column's edge. A saved title's highlight band is `1lh + 0.5px` tall (`.item-text`, `--saved-band`): each line's band is snapped to device pixels, which leaves a hairline seam between lines, and the half pixel closes it.
