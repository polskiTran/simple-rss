# Treat publisher content as hostile: refuse entity declarations, bound every body, and rebuild Markdown from an allowlist

Feed documents, OPML files, and Original webpages are written by people this installation does not trust, and ADR 0005 bounds how they arrive, not what they contain. Three rules govern what happens to them after they arrive. First, a Feed document or an OPML file that contains a DOCTYPE or ENTITY declaration is refused before it reaches the XML parser (`ingestion/xml.ts` `declaresXmlEntities`), which closes external-entity and entity-expansion attacks before any parser sees them. The cost is that a legitimate RSS 0.91 file carrying its DOCTYPE is refused as `unsupported_feed`.

Second, each Feed Content body has its own ceilings, on top of Retrieval's ceiling for the whole document, so that one hostile entry cannot monopolise conversion or recursive traversal. `ingestion/feed-content.ts` `normalizeFeedContent` reads at most the first 524,288 characters of a body, visits at most 20,000 DOM nodes to a depth of 64, keeps at most 512 table rows and 64 columns, caps each link or image destination at 4,096 characters and all of them together at the input ceiling, and marks the Feed Content truncated when any ceiling is hit. What it stores is bounded separately: `FEED_CONTENT_MAX_BYTES` is 256 KiB of serialized Markdown. That bound covers stored Feed Content only. Reader View signs image URLs when it answers, so delivered Markdown is larger than what is stored, and nothing downstream may assume that delivered Feed Content fits the stored budget. When Markdown exceeds the budget, `boundedMarkdown` cuts the Markdown AST and serializes the prefix again, searching for the longest prefix that fits. Slicing the serialized string was rejected because a cut there can leave a code fence open, a link half-written, a list's nesting broken, or a surrogate pair split. GFM tables are serialized without pipe alignment (`tablePipeAlign: false`), because alignment pads every row to its widest cell and so turns one oversized cell into the same width on every row.

Third, Reader Markdown is rebuilt rather than filtered. `markdown/markdown-policy.ts` `readerMarkdownTree` walks the Markdown AST and emits only node types it names: paragraphs, headings, block quotes, lists, code, thematic breaks, tables, math, text, breaks, emphasis, strong, inline code, links, and images. Strikethrough and link references keep only their text. Anything else, raw HTML included, is dropped rather than passed through, so a construct the policy does not name is excluded by default. A link whose destination is not absolute `http` or `https` keeps only its text, and such an image, or one carrying URL credentials, is dropped. The same policy applies to Feed Content at ingestion and to an Original webpage after extraction, so both Reading Sources reach the client in one dialect. Feed Content is stored with absolute destinations, already resolved at ingestion against declared XML bases and the post-redirect Feed address, so `reader/reader-items.ts` applies the policy again at delivery, to sign image URLs, without a base URL. Every caller states what happens to image destinations, since no default could be right for both stages: ingestion keeps them (`'preserve'`) so the stored Markdown stays durable, and both Reader deliveries, Feed Content and an extracted Original webpage, sign them (`{ sign }`) so the client loads each image through the image proxy.
